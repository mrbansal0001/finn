E24 Guidance extraction vs the 84-statement gold set (BEL + Deepak, 8 transcripts; models discovered at runtime: gemini-3.5-flash-lite 'fast', gemini-3.8-flash 'smart'; all on the free tier):
- single pass, light model: recall 55%, precision 55%, quotes verified 99%; strong model: recall 56%, precision 52%, and 2/8 calls hit the free-tier limit (fell back to gpt-4o-mini, $0.016) -> the stronger model is not better; light model kept.
- diagnosis by hand: (a) scorer too strict (a correct find named differently, e.g. "order inflow 30,000-32,000" vs "QRSAM order receipt"); (b) closing-remark restatements counted as false positives; (c) genuine misses concentrated in long calls (Deepak Q4FY26 2/7, BEL Q4FY26 6/14) -- a single pass under-reads.
- fair scorer (programme/figure match on the same page; restatements neutral; strict numbers also reported): precision 51% -> 69%, recall unchanged ~50%.
- prompt listing what counts (conversational timing, cost ratios, mix targets; one item per commitment): recall 50-52%, precision 69-72%.
- overlapping 6-page windows, merged in code: recall 79-80% (two runs), precision 50-53%; dropping 'directional' items with no number or date: precision 61%. 40 calls per run, $0.
- hand check of 30 unmatched predictions: ~50% genuine checkable commitments the gold set didn't label (e.g. "executing more than 90% of that order before this financial year"), ~20% restatements, ~30% vague. Effective precision is therefore nearer 80%.

E25 Results-table reading with the light model (18 portfolio results PDFs, 11 Nov):
- a wide named-field schema (~20 fields) made the model fill 2-3 fields (Titan: revenue, tax, total income only) -- and the check passed it because it compared only fields present. Fixed both: the check now requires the core lines (revenue/PBT/PAT; banks interest earned/expended/PAT).
- switched to row transcription (label as printed + one number per column) mapped to fields in code: 10/18 pass.
- label normalisation ('1 Income a) ...', '(Loss) / profit ...'), 'total revenue from operations' preferred over its sub-line, revenue derived from printed totals when only sub-lines exist (Titan), 'exceptional' anchored so 'profit before exceptional items' isn't taken: 12/18.
- the model varies run to run; up to three attempts per page (text, image, image), keeping the first that passes every check: 16/18 pass (14 reconcile arithmetically, 2 also equal the Integrated Filing XBRL: Kalyan, Cochin). The 2 failures (tangled layouts) stay hidden.
- E25 addendum: checked Titan against its PDF page by eye: revenue had been derived as total income - other income (21,285), but total income also held a 671 cr fair-value gain on a put-option liability; true revenue 20,337 + 277 = 20,614. Fixed: revenue from its printed sub-lines; any other income line is non-operating (kept out of EBITDA, named in the copy). Profit swings across zero are described in words, not percentages (Tata Chemicals "swung to a loss of 50 cr", not "-132.5%"). 17/18 tables now pass.

E26 Promise linking, model vs code (gold statements as input; pairwise precision / recall):
- deterministic (names + facets + FY): BEL 0.88 / 0.70, Deepak 0.75 / 0.67 -- identical every run.
- model-assisted (light model assigns each new statement to a thread or 'new', with a code guard refusing unlike units/facets): BEL 0.67-0.79 / 0.58-0.60, Deepak 0.93-1.00 / 0.78 over two runs.
- hybrid (deterministic for shared programme names, model for the rest): BEL 0.78-0.83 / 0.42-0.70, Deepak 0.65-0.76 / 0.67-0.72 over three runs -- noisy.
-> deterministic linking kept as the default (as accurate on average, stable, free, explainable); model linking behind FINN_LINK=model. Also fixed: relative periods resolved against the call ("current financial year" on a Jan call = FY26; "this year" on a May call = the new FY); promises whose period has ended show as closed, not "went silent".


E27 Model-built ledger review (BHARATFORG via a live visitor request, PERSISTENT, DIXON, LGEINDIA; 12 Nov). - model responses are now cached by request hash, so these rebuilds cost nothing and are reproducible.
- still true: long calls give long ledgers (Dixon 106 rows, mostly 'too early' because most targets are FY27-FY28). The UI shows slipped/reset first and 20 rows before 'Show all'.
