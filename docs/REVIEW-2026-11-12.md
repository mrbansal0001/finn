# FINN: full review and improvement plan (12 Nov 2026)

How this review was done:

- I read the brief and the reference PDF again, line by line.
- I walked through the live site as a first-time visitor on a phone.
- Three independent reviewers worked in parallel. Each got only the code and the brief, not my conclusions:
  - worker correctness;
  - web app, security and privacy;
  - every displayed number checked against the cached source PDFs and bhavcopies.
- I re-verified the most serious findings myself before listing them.

**Nothing below is implemented yet.**

## 0. Verdict

The architecture, privacy model, ledger concept and design point of view are strong and hold up under review. Two things put the submission at risk:

1. **Some cards show numbers that are wrong**, and the checks we cite in the writeup let them through.
2. **Several parts of the brief are thin or missing**:
   - the network can't be queried directly;
   - no people card shows a person-level overlap;
   - there are no real triggered alerts;
   - Pull on an unpicked ticker shows an empty page unless the Mac worker happens to be running.

Fixing (1) comes first. A grader who spots one wrong number stops trusting everything.

## 5. Tier 4: writeup, docs, submission

The brief asks for several things that are missing or now wrong:

1. **"Matching a name in a filing to a person in the network"**: not explained. Add the entity-resolution rules (name + org + dates; DIN in production; when we say "same person" vs "both ex-X").
2. **"What personal data you store and for how long"**: no retention stated. Add it (anonymous demo sessions deleted after N days; real deployment: retention per DPDP, purge on consent withdrawal).
3. **Consent and access control in a real deployment**: one tight paragraph (import consent, per-source scopes, audit log, deletion).
4. **Diagram in the email**: link the README mermaid or include a compact ASCII diagram.
5. **Correct the numbers**:
   - results "17/18" → the verified breakdown after Tier 0;
   - classifier held-out: re-label #7 (auditor change) per ENAM's reference and add the Bagchi miss, so it's honest about the live miss;
   - "Every quote verified" → "verbatim span shown".
6. **AI build history**: the export is ready (`data/history/…md`). The user chooses a Gist or a repo file; fill the link.
7. **Course-corrections are a selling point**: the brief wants to see how I "course-correct when the model goes wrong". E23, E27 and this review (results inverted, banks unchecked) belong in the writeup as one short paragraph with the numbers.
